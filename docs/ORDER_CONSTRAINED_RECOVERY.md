# 从查询的部分顺序恢复实例密钥

研究问题：噪声下密钥已恢复，绝对残差仍可能拒绝合法图；亮度饱和后，原型又把仍含比较信息的像素全部删除。这里研究查询直接给出的不等式约束如何决定密钥恢复，而不是放宽原残差阈值。结果以冻结协议和逐样本记录为准。

## 恢复关系

继续使用已有辅助格式`h=x+αBs`，其中x为64×64×3的块内顺序统计量，s为128个随机±1符号，B由服务端秘密和记录标识派生。当前探针固定α=0.05，并加入相同α的原前向解码消融；不与旧α=0.3的性能混作单一因素对照。

查询y定义部分序集合：

`C(y) = {z: y_i < y_j => z_i <= z_j}`，三个颜色通道分别定义顺序。

若查询由参考经过逐通道单调非减处理得到，x属于C(y)。当两个查询值同为饱和白或饱和黑时，二者之间不强制相等，也不强制先后；与其他亮度组的比较关系仍然保留。空间重采样、旋转、遮挡和非单调处理一般不满足这个关系。

求解`min_{s∈[-1,1]^128} 1/2 dist(h−αBs, C(y))² + ε||s||²/2`，ε=1e-8只用于数值正则化。将连续解逐位取符号，验证已登记密钥的确认哈希并实际解封载荷。成功解码后不再加图像残差阈值。噪声会造成部分比较反转，进入同一个优化问题的投影误差；准确恢复是否仍成立由实验决定，未假定任意噪声分布。

相同查询值内先按当前待投影值排序，再做PAVA并恢复原索引。交换论证说明最优投影可保持这些组内的原相对次序，因此该实现没有把饱和组强制压成同一个值。独立小规模SLSQP约束优化用于核对该投影；这是数值实现检查，不代替一般证明。

## 相对完整参考的独立价值怎样验收

拥有完整x、相同辅助信息和算法的验证器能模拟恢复器，所以恢复不会凭空增加图像判别信息。实验至少同时保留：原前向参考拟合、与本候选使用同一部分序的直接参考距离、九模板SSCD。若仅优于原前向拟合而与直接顺序匹配相同，收益归属于编辑关系。

恢复层可单独检验的能力是：验证过程只读取登记辅助记录和查询，实际返回128位随机密钥及认证载荷；不读取原始参考图或明文实例密钥。必须同时报告辅助记录大小、服务端秘密、随机密钥生成/擦除边界，以及错误查询返回情况。该实现未证明辅助信息隐藏原图，也未证明持有服务端秘密时仍必须依赖真实查询；不能由哈希位数推导图像FPR。

## 预先约定的验证

开发探针只用既有前10实例的原图、既有噪声、六倍亮度和同提示词不同实例。完整开发验证保留所有既有编辑和作者Imprint/Reprompt/Reprompt+输出。确认前冻结实现、辅助生成、阈值和对照；新处理采用[ICML2024 WAVES](https://proceedings.mlr.press/v235/an24a.html)的原作者实现及五档强度，源码commit1477635d306d6f8c77a588e6441bd4ba301a1f7a。

计划确认类型为此前协议未执行的contrast、rotation和resizedcrop；brightness/noise只作为已见问题复测，不能称为未见类型。所有类型保留完整分母，未见几何处理失败也保留。源码阅读是预先设计的一部分，“未见”指未参与本项目模型开发、阈值选择或效果查看；并非声称未曾知道这些编辑的定义。
