# 发布实例的可恢复内容绑定

研究目标是让水印认证对应具体的一次图像发布：合法压缩、缩放等处理后仍能恢复该实例的验证材料，同提示词其他图片和已有伪造输出被拒绝。原生GS/TR/PRC载体保持各自定义。完整实验、失败和冻结协议保存在[报告索引](../reports/README.md)，当前执行状态只由[project_state.json](../project_state.json)维护。

## 已经成立的实现与观察

实际恢复链路已运行：登记最终图，构造实例区域，BCH或RS恢复128位密钥，认证解封原生材料，并由作者检测函数验证查询图。成功密钥与材料逐字节核对。实现采用服务端秘密，属于计算型密钥绑定；内容熵和经验误接受率仍需单独测量。

- [表征对照](../reports/instance_representation_20261113/report.md)：最终图参考下，SSCD处理图428/450、不同实例误匹配1/50；SemBind语义码对应420/450、42/50。辅助图身份漂移与提示词级不变性是两个不同问题。
- [实例方向恢复](../reports/instance_edit_quotient_20261113/report.md)：八方向版本的最大恢复为473–477/500，共同90%校准点为455/460/457；int8九模板SSCD为448/500。95%校准恢复目标尚未达到，辅助记录9408字节。切空间校正和可靠位选择已有方法基础。

## 密钥恢复应增加什么价值

设经过认证的发布记录对应内容码w、辅助数据P和原生载体密钥K。若恢复器在d(w,w')≤t内完整正确、球外拒绝，而且密钥确认只接受本记录的K，则最终接受事件为：

`Accept(x, record) = [d(w,w') ≤ t] AND NativeDetect(K, x)`。

因此，在这些条件下，距离门控和恢复协议具有相同接受集合。若实际译码只覆盖区域的一部分，还要计入这些合法恢复失败。一般模糊提取器只保证规定距离内正确，球外拒绝需要额外约束，见[标准定义](https://www.cs.bu.edu/~reyzin/papers/fuzzy.pdf)。

防伪收益由可恢复区域的实例分离决定；密钥封装则可能改变存储、密钥访问和验证方式。这些价值应分别证明。对任意分布，`P(content AND carrier) ≤ min(P(content), P(carrier))`；乘积公式需要独立性依据。原生载体、图像内容与伪造生成过程存在依赖，联合判定必须实际记录。

## 目前的机制判断

未知处理要求保留同图变化；实例区分要求保留图与图之间的差异。扩大统一半径、用查询自拟合参考、移除过多方向，都可能同时消去这两种差异。共同频谱试图利用额外的反演观测解决这个冲突，实测暴露出普通实例区分和Imprint区分的差别。Reprompt进一步暴露出另一层问题：即使同提示词独立图被拒绝，继承参考图部分结构的重新生成图仍可能恢复同一实例密钥。

成熟局部匹配提供了更强的实例证据，但局部特征、几何匹配、模糊金库和编辑估计结合译码都有直接先例。本轮已经实际检验局部恢复、几何配准、参考侧区域隔离和可见性擦除：恢复率与防伪率的矛盾仍然存在。当前最具体的问题是：**查询中哪些信息确实因编辑而消失，哪些仍然可见却与发布实例相矛盾；恢复条件如何保留后者的否决作用。** 这需要新的证据关系，单纯增加纠错半径、复制匹配器或可变集合长度都已有直接基础。

可见性原型用灰度跨度识别平坦缺失区，仅提供了一个较窄的判别。成功译码要求至少40个一致的可见符号，但这种局部粗次序也能被Reprompt保留。它给出的是“这些次序仍一致”的证据，剩余清晰内容是否已被替换不在当前关系中。配准条件提供额外约束，却以拒绝大量合法图为代价。

## 下一机制的具体研究问题

值得继续检验的假设是建立**受编辑状态约束的证据删失关系**：合法编辑可以使部分实例细节不可观察；仍清晰可见的细节应参与同一实例的一致性检查。恢复器只能依据事先定义、可核验的编辑状态删失证据，不能根据“该位不匹配”或“这次译码失败”自行把矛盾改成缺失。剩余实例证据必须达到冻结的最低要求，之后才解封同一密钥。

这目前是研究假设，尚未实现或验证为新方法。需要先解决两个相互关联的问题：如何在未知编辑下估计信息可观察性；如何让证据表达对重新生成的实例变化敏感。把粗结构、细节或现成描述子分别接上若干门槛，并未自动解决这两个问题。

一个可证伪的评估路径是：先固定分辨率、参考记录和计算预算，检验候选的“可见矛盾”能否在合法编辑下保持较小、在已有Reprompt下保留足够间隔；再检查把编辑状态换成固定值、打乱来源、或使用全信息参考时的变化。状态估计若随查询实例改变而解释掉差异，候选即失败。只有连续证据关系已经在同合法检出率下优于SSCD/CopyNCE，或明确减少存储与密钥访问成本，才继续将它构造成真实恢复器。已有攻击原样执行，不用新攻击或改进攻击来形成机制。

编辑参数估计与分布式信源认证在TIP2012已经联合研究；可变特征集合导致纠错阈值漂移，也已有专门分析。因此这一假设的创新性必须落到新的可恢复关系、可证明的协议性质或实测的成本收益，而非给既有错误／擦除译码换名。普通同提示词负例、Imprint和Reprompt始终分别报告。

下一机制需要事先说明：

1. 查询中的什么观测能识别合法编辑，同时保留实例差异；它比现成描述子或配对匹配多了什么信息。
2. 辅助记录如何定义可恢复集合，恢复函数实际读取哪些私有和公开输入；成功恢复必须对应唯一的发布实例材料。
3. 相同合法通过数下，实例误接受和原样完整预算攻击接受是否降低；或者在相同接受集合下，登记存储、查询或密钥访问成本是否明确降低。
4. 编辑类型从实例登记与本轮阈值校准中同时留出后，收益是否仍成立；公开编码器预训练用过的增强另作说明。

## 后续实验的验收标准

新来源按实例拆分开发、校准和确认，冻结方法后再读取确认结果。全部合法参考进入分母。先比较连续区域和强门控，再实际恢复密钥与原生材料；逐条件列出内容通过、密钥恢复、原生通过和联合通过。只有同时满足机制可解释、同工作点收益或明确协议收益、实际恢复正确性、成本可核对，才将候选升级为论文主线。
