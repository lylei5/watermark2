任务目标是建立三个可复核的完整防御入口，再以原论文设置检验其数值表现。新防御训练暂缓。运行状态只维护于project_state.json；已执行结果、失败及规格差异均保留。

## 验收层次

1. **来源与环境闭合。** 干净固定源码、模型权重哈希、实际依赖及兼容性差异；不修改第三方数值或攻击代码。
2. **完整正常链路。** 每个方法独立原生生成、查询重提取、反演与布尔判定；保存图像、反演潜变量、连续分数和逐条决策。组件测试与正常链路通过不等于论文复现。
3. **已有发表评测。** 原生干净、无水印、良性处理和完整预算的既有攻击；原GS对照同时验证攻击有效性。检查代码索引50/100/150与实际更新51/101/151的区别。
4. **论文规格与共同工作点。** 分别报告各论文原生设置和同条件比较。不能把不同载体、反演器或阈值下的数字直接排名，不能把理论或小样本零误报写成经验1e-6。

## 实施边界

SemBind发布的是组件和demo；用户已确认没有额外作者代码，授权按论文补齐并明确差异。论文补齐部分必须标明，未公开的GS++完整实现不能自行拼装冠名。PGID的现有小样本原生结果继续保留，并在新源码固定版本下核对数值路径。SEAL原始入口不输出最终布尔标签，使用最终论文算法3与补充§9.1补齐计数判定；不把穷举最小距离当作语义判定。

SEAL公开源码使用投影seed42，论文算法2描述secret salt。两条路径独立保留：公开代码直接复现；论文路径由seal_paper_simhash.py补齐，并声明哈希序列化和Gaussian RNG选择。两者分别验证，不混称为作者同一实现。

只使用249的空闲GPU7、5、4，最多三张，禁用GPU6。已冻结的100提示词反演任务按退出事件完成；随后安排原生基线任务。实验期间继续源码、规格和报告工作，不持续轮询。不发送作者邮件或公开issue，缺项先记录为可核查问题。

## 本轮入口和验证范围

| 入口 | 具体执行 |
|---|---|
| `run_phase1_probe_worker.py --stage verify` | 原GS OTP及GS-S，100提示词、300次完整DPM反演、400条决策 |
| `run_seal_native.py --run RUN --shard 0/1/2` | 官方SEAL正常生成、候选自身语义参考和无水印对照，100提示词 |
| `run_sembind_prc_native.py --run RUN --shard 0/1/2` | 原PRC与PRC-S，sigma0.5，6来源的12张水印图及辅助图无水印对照 |
| `run_pgid_native.py --run RUN --shard 0/1/2` | 原样调用PGID run.py，GS/PGID-R、10案例、完整151更新、全部三检查点 |

每个RUN须为249根目录runs下的冻结协议目录。工作进程校验源码哈希并拒绝覆盖已有结果；复跑应使用新的目录和保存的同一协议，不复用结果目录。三个队列由进程退出事件串行衔接，只有每个队列内部使用三张GPU。

SemBind专用掩码在`sembind_binding.py`，只有论文的平铺、截断、私有置换和符号乘法。sigma0/.5/1的300次精确解绑定检查已完成。GS-S的sigma1布局与冻结原GS链路保持一致。PRC私钥和512位消息只在249生成与保存，6条原码Encode/Decode往返通过；图像通过率须另等完整反演，不能用这6条CPU往返替代。

PGID的GS载体使用官方公开fixture密钥和扁平重复，原GS-S使用原GS默认OTP及空间重复。保留两条原生路径，并明确其不同；这轮结果不作同载体、同工作点排名。TR-S、GS++-S及PGID其他载体的图像验收尚未覆盖，不能宣称全论文矩阵完成。
